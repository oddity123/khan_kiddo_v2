## 总判断

功能名定为 **「定向复练提示词」**，页面区块文案为 **「带着薄弱点再练一轮」**，主按钮为 **「生成复练提示词」**。

分析结果已经提供本场 Top 1–3 行动卡、诊断、教练提示、证据句和成长卡，不需要为了生成复练提示词再次调用大模型。前端只负责选择训练素材，选择完成后将必要信息提交到后端；后端统一校验、排序、裁剪并套用提示词模板，便于后续集中维护训练规则和文案。

登录用户和游客共用同一个接口与请求结构。游客分析只保存在前端内存，后端无法通过 `analysisId` 回查，因此两类用户都采用「提交已选内容」的统一模式，不拆分 ID 回查和内容提交两套链路。

首版组装过程：

- 不调用 LLM，不消耗 AI Key；
- 不保存请求、生成结果或用户编辑后的提示词；
- 不上传完整对话，只提交选中的 Top 项、例句和词汇表达；
- 不建设数据库模板或管理后台，模板先由后端资源文件统一管理。

## 产品行为

### 1. 入口

- 普通分析详情页和游客分析预览显示入口，管理端详情不显示。
- 有 Top 1–3 或「不会表达」素材时，显示可用的「生成复练提示词」。
- 两类素材都没有时，显示禁用状态「本场无需专项复练」。
- 登录用户点击入口后先静默刷新一次详情，尽量取得异步生成完成的本场词汇卡；刷新失败时继续使用当前页面已有数据。

### 2. 训练素材

- Top 项固定取本场 `actionCards` 的前 1–3 项，按 `rank` 升序排列，不允许用户取消。
- 登录用户的附加词汇候选来自本场 `growthCards` 中 `type = vocab` 的卡片。
- 游客没有持久化成长卡，使用本场 `educationalSummary.chineseExpressions` 生成临时词汇候选。
- 习惯成长卡不进入附加词汇列表，避免与 Top 1–3 重复。
- 附加词汇默认不选，用户最多勾选 3 项；达到上限后禁止继续选择未选项。

### 3. 生成与编辑

1. 用户点击「生成复练提示词」。
2. 弹窗立即进入加载状态，前端用 Top 项和当前选中的词汇调用后端接口。
3. 后端返回后，在可编辑文本框中展示提示词。
4. 用户改变词汇选择后，点击「按所选卡片更新」重新请求后端；更新会明确覆盖文本框中的手动修改。
5. 「复制提示词」始终复制文本框当前内容，包括用户的手动编辑。
6. 初次生成或更新失败时保留当前选择，显示错误和「重新生成」入口。
7. 关闭后不保留提示词、选择或编辑历史；再次打开重新按默认状态生成。

## API 设计

新增允许游客访问的接口：

```http
POST /api/conversation/practice-prompt
Content-Type: application/json
```

### Request

```json
{
  "goals": [
    {
      "rank": 1,
      "title": "过去发生的事情要使用过去时",
      "diagnosis": "本场多次使用现在时描述已经完成的动作",
      "coaching": "先确定时间，再选择动词形式",
      "originalSentence": "Yesterday I go to the store.",
      "targetSentence": "Yesterday I went to the store."
    }
  ],
  "vocabulary": [
    {
      "front": "售后服务",
      "back": "after-sales service",
      "originalSentence": "How can I say 售后服务?"
    }
  ]
}
```

对应接口类型：

```ts
interface PracticePromptRequest {
  goals: PracticePromptGoal[]
  vocabulary: PracticeVocabulary[]
}

interface PracticePromptGoal {
  rank: number
  title: string
  diagnosis?: string
  coaching?: string
  originalSentence?: string
  targetSentence?: string
}

interface PracticeVocabulary {
  front: string
  back: string
  originalSentence?: string
}
```

### Response

```json
{
  "prompt": "你是我的英语口语陪练……"
}
```

```ts
interface PracticePromptResponse {
  prompt: string
}
```

### 校验规则

- `goals` 和 `vocabulary` 至少有一个非空，否则返回 400。
- 两个数组分别最多 3 项。
- `goal.rank` 仅允许 1–3，同一请求内不得重复，服务端按 rank 升序输出。
- `goal.title`、`vocabulary.front`、`vocabulary.back` 必填。
- DTO 使用 Jakarta Validation 限制数组和各文本字段长度，防止公开接口接收超大请求。
- 服务层统一 trim 所有文本，空白可选字段按缺失处理。
- 词汇项按规范化后的 `front + back` 组合去重。
- 非法数量、重复 rank、空必填字段和超长文本统一返回 400，不静默吞掉客户端错误。

- [ ] 在 `ConversationAnalysisController` 增加 `POST /practice-prompt`。

- [ ] 在 `backend/src/main/resources/templates/prompts/` 新增复练提示词模板。
- [ ] 在 `PromptLoader` 增加对应模板读取方法。
- [ ] 前端不得保留另一份完整提示词模板，避免两端行为漂移。

模板保留动态占位符，例如：

```text
{goals}
{vocabulary}
```

Java 服务只负责把已清洗的数据格式化成动态区块；角色定义、训练节奏、纠错方式、结束条件和总结格式全部写在资源模板中，以便后续集中修改。

### 2. Top 项输出

每个 Top 项最多输出：

- 排名与用户可理解的标题；
- 本场具体诊断；
- 教练提示；
- 一条「原表达 → 推荐表达」。

缺少诊断、提示或例句时省略对应行，不输出空标签。不得输出 `pointId`、`habitKey`、内部评分或完整对话原文。

### 3. 词汇输出

- 每项输出「想表达的内容 → 推荐英文」。
- 有证据句时最多附带一条原句。
- 没有附加词汇时，整个词汇训练区块从最终提示词中省略。
- 只有词汇、没有 Top 项时，生成词汇定向练习版本，不要求伪造 Top 目标。

## 提示词训练规则

服务端模板必须稳定要求 GPT：

1. 根据目标自动设计一个能自然触发这些表达的真实情景，直接以角色身份开始，不先讲课。
2. 采用语音优先风格，每轮只回复 1–3 句、一次只问一个问题，然后等待用户回答。
3. 按 Top 排名安排触发优先级；附加词汇只是加练内容，不与 Top 项平级。
4. 不提前泄露用户应该说出的目标句或词汇答案，而是在情景中自然制造使用机会。
5. 用户在目标点出错时，先正常回应对话内容，再用一句中文指出问题并给出可复述的英文示例。
6. 非目标小错除非影响理解，否则不打断当前对话。
7. 完成 8 个用户回合或用户主动说「结束练习」后结束情景。
8. 最后用中文总结：各 Top 目标的使用情况、推荐表达、选中词汇是否使用，以及下一次最值得继续练的一点。

## 测试与验收

### 后端单元测试

- [ ] 3、2、1、0 个 Top 项均能按规则组装，其中 0 个 Top 时必须至少有词汇。
- [ ] Top 项始终按 rank 排序，不受请求数组顺序影响。
- [ ] 可选字段为空时不产生 `null`、空标签或多余占位符。
- [ ] 词汇项去重、trim 和无词汇区块省略正确。
- [ ] 最终结果不包含内部 ID、评分或完整对话。
- [ ] 生成过程不会调用 LLM、数据库或成长卡服务。

### Controller 与校验测试

- [ ] goals/vocabulary 同时为空返回 400。
- [ ] 任一数组超过 3 项返回 400。
- [ ] rank 越界或重复返回 400。
- [ ] 必填字段为空、只有空白或超过长度限制时返回 400。
- [ ] 未登录请求可以成功生成提示词。

### 前端人工验收

1. 登录用户有 Top 和本场词汇卡：默认只生成 Top，最多追加 3 个词汇。
2. 游客有 Top 和中文表达：使用临时候选正常生成，不要求登录或制卡。
3. 只有词汇没有 Top：入口可用，生成词汇定向练习提示词。
4. 完全没有训练素材：显示「本场无需专项复练」，不发请求。
5. 用户修改提示词后直接复制：剪贴板内容必须是修改后的版本。
6. 用户修改提示词后再更新词汇选择：明确覆盖编辑内容并展示服务端新结果。
7. 接口失败：保留选择，可重新生成，不关闭弹窗。
8. 管理端分析详情：不显示复练入口。
9. 移动端：弹窗、选择区、文本框和操作按钮均可正常使用。
