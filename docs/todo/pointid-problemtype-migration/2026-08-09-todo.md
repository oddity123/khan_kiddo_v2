# PointId 真源化与 ProblemType 退役 TODO

日期：2026-08-09  
状态：backlog（技术治理；不是当前 MVP P0）  
范围：以 `pointId + PointDictionary` 取代旧 `ProblemType` / `problem_types` 作为新分析的分类、评分与统计依据。

## 结论与边界

`pointId` 已是 Stage 2 的唯一模型输出。当前 `problem_types` 由后端从字典反查写入，属于重复的旧聚合标签；它不再是领域真源。

本任务的目标是：

```text
新数据：pointId + 字典 → 所有分类、展示、评分、统计
旧数据：仅在 pointId 缺失时读取 problem_types 兼容展示
最终：停止写入并移除 problem_types / ProblemType
```

不把本任务与表达状态（`ERROR / RISK / UNNATURAL / OPTIONAL`）、Root Cause 或 Stage B 改造捆绑实施。前者是诊断产品能力，后者是数据模型退役；两者应分别验证价值和风险。

## 当前问题

- `problem_types` 不提供 `pointId` 之外的新信息，却形成第二分类真源。
- 当前字典的多数 `*_OTHER` 映射为 `Structure`，会污染首页统计、RAG 历史统计和旧分布。
- `ProblemType` 同时承担展示中文名、严重度、评分权重、SQL 聚合和 RAG 过滤，职责过多；它与 `familyId` / `channel` 的边界也不一致。
- 旧行只有 `problem_types` 时无法准确反推具体 `pointId`，不得伪造回填。

## 目标数据约定

| 概念 | 新数据约定 |
|---|---|
| 分类真源 | `point_id`，必须是当前字典中的合法 ID |
| 分类解释 | `PointDictionary` 提供 `familyId`、`channel`、标题、`errorLevel`、卡片策略 |
| 历史语义 | 在 `conversation_analysis` 保存 `point_dictionary_version`；字典版本变化不得悄然重解释新记录 |
| 评分 | 字典中的 `scoreProfile` / `scoreDimensions` + `errorLevel`；不再依赖 `ProblemType` 枚举名 |
| 统计聚合 | 服务层按 `pointId → familyId` 聚合；首页默认展示 family，不展示无上下文的细叶子 |
| 旧兼容 | 仅 `point_id IS NULL` 时读取 `problem_types`；不参与新统计口径 |

`family_id` 不作为第一阶段必须落库的字段：先由字典在服务层反查，只有确认 SQL 聚合性能成为问题时才作为可重建的冗余缓存加入。

## 实施顺序

### P0：冻结边界与测试基线

- [ ] 在代码和文档中标注 `ProblemType` / `problem_types` 为 deprecated；禁止新功能依赖它。
- [ ] 为所有新写入的 `pointId` 增加合法性断言；无效 ID 必须经现有 sanitizer 落到合法 fallback。
- [ ] 为现有旧记录保留 `point_id = NULL` 的读取测试。
- [ ] 固定一组“新记录只靠 pointId”和“一组旧记录只靠 problem_types”的详情、评分、首页统计兼容测试。

验收：没有新增业务代码将 `ProblemType` 当作分类真源；旧数据仍可打开详情。

### P1：评分脱离 ProblemType

- [ ] 在字典定义评分所需字段：至少 `errorLevel`、`scoreProfile`、`scoreDimensions`；保留现有分数体验作为迁移基线。
- [ ] `PerformanceScoringInput` 改为传递 `pointId`（或已解析 `PointDefinition`），删除 `problemTypeKeys`。
- [ ] `WeightedNaturalnessPerformanceScorer` 按字典评分字段计权和判定严重度，不再 import `ProblemType`。
- [ ] 将 `performance-scoring.yml` 从枚举名权重迁到 `scoreProfile` / 维度配置。
- [ ] `EducationalSummaryParser`、详情补算和成长卡重算统一从字典取严重度。

验收：同一批含 `pointId` 的新分析在迁移前后分数和四维分数符合明确的基线；评分路径不再引用 `ProblemType`。

### P2：新写入和读取路径真源化

- [ ] `ConversationAnalysisServiceImpl` 新分析仅写 `point_id`，不再从字典写 `problem_types`。
- [ ] 新增分析主表字段 `point_dictionary_version`，写入当前字典版本；旧记录保持空值。
- [ ] `ConversationAnalysisItem`、MyBatis mapper、保存 DTO 去除新写入对 `problemTypes` 的要求。
- [ ] 详情页 API 从 `pointId` 反查显示标题、family、channel、严重度；`type` 仅作为旧 API 展示兼容字段。
- [ ] 成长卡和 HabitCard 重算从 `PointDefinition.errorLevel` 取值，不再读取 `row.problemTypes`。

验收：新分析数据库行即使 `problem_types` 为 `NULL`，详情、评分、行动卡和成长卡均正常。

### P3：首页、历史统计和 RAG 迁移

- [ ] Mapper 增加按 `point_id` 的计数和筛选查询；新统计不再 `GROUP BY problem_types`。
- [ ] 首页“最常见问题”、近 7/30 天分布、严重问题数按 `pointId → familyId` 统计；API / 前端命名改为 knowledge point 或 family。
- [ ] 最近错句标签从 `pointId` 映射字典标题或 family 标题。
- [ ] RAG 数据库工具参数从 `List<ProblemType>` 迁为 `pointIds` / `familyIds`；自然语言助手的工具说明同步更新。
- [ ] RAG 文档正文与 Qdrant metadata 改存 `point_ids` / `family_ids`，不再写 `problem_types`。

验收：新数据的首页、复盘中心和 RAG 无任何 `ProblemType` 查询；family 聚合不再把各类 `*_OTHER` 误报为 Structure。

### P4：前端和公共契约清理

- [ ] 前端筛选、分布和错误标签以 `pointId` / `familyId` 为主，不再依赖 `AnalysisError.type`。
- [ ] `errorTypeDistribution` 仅对旧详情返回；新详情只使用 `familyDistribution`。
- [ ] API 类型把 `ProblemTypeStat` 替换为带 `pointId` / `familyId` 的统计对象。
- [ ] 旧保存接口的 `error.type` 保留一个兼容发布周期后移除。

验收：前端新记录展示和筛选无需 `type` / `errorTypeDistribution`；旧详情仍有降级展示。

### P5：旧字段退役

- [ ] 观察期内确认所有新写入均有合法 `point_id`，且首页 / RAG / 评分没有旧字段依赖。
- [ ] 保留旧数据只读兼容，直到产品确认历史记录无需继续支持或完成单独归档。
- [ ] 删除 `idx_problem_types`、`problem_types` 列、`ProblemType` 枚举、对应 DTO / mapper / RAG metadata / 测试。
- [ ] 从 `point-dictionary-v1.json` 删除 `problemType` 字段。

验收：全仓生产代码不再出现 `ProblemType`、`problemTypes`、`problem_types`；完整测试、前端构建和历史兼容策略通过验收。

## 迁移约束

- 不根据旧 `Tense`、`Structure` 等宽泛标签猜测具体 `pointId`。
- 不在本任务中扩张 pointId 字典、引入表达状态、Root Cause 或用户 Profile。
- 不先删数据库列；必须先完成评分、统计、RAG 与旧详情读取迁移。
- 新功能若需粗粒度聚合，一律使用 `familyId`；若需可训练行为，使用 `pointId` / `habitKey`。

## 当前优先级

本任务暂列 P2 技术治理。当前 MVP 更高优先级是：核对已有分析的成功率、时延、误报与用户是否完成第二次分析；只有确认诊断输出可信、分析激活路径顺畅后，再启动本迁移。
