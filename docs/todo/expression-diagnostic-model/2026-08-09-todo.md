# Expression Diagnostic Model：状态、根因与目标 Profile TODO

日期：2026-08-09  
范围：对话分析系统的诊断模型、Stage 2 / Stage B、评分、行动卡和用户学习目标。

## 总判断

当前系统已经具备三阶段分析、pointId 知识点字典、family 聚合、行动卡和多维评分的工程骨架，但仍主要是「错误分类系统」，还不是完整的「二语表达诊断系统」。

当前方法论落地度约为 **58 / 100**。本任务完成后，目标提升到 **72–78 / 100**。

核心原则：

> A sentence should not be corrected merely because a better sentence can be generated.

中文含义：能够生成更好的表达，不代表原表达存在问题。

## 目标架构

当前 Stage 2 同时承担错误定位、问题判断、整句改写和展示决策，职责过重。后续拆为观察层与诊断裁决层：

```text
Stage 1：Conversation Separation
    ↓
Stage 2A：Diagnostic Observation
    ↓
Stage B：Diagnostic Adjudication & Aggregation
    ↓
Stage 3：Goal Filter + Learning Priority + Growth Card
```

### Stage 2A：Diagnostic Observation

只负责发现可疑的语言信号，不直接决定用户是否应该看到，也不承担最终评分。

建议输出：

```json
{
  "utteranceId": "u_3",
  "span": "make propaganda for",
  "pointId": "LEXICAL_GAP",
  "signalType": "LEXICAL_SELECTION",
  "localFix": "promote",
  "reason": "propaganda 带强政治或操纵性含义"
}
```

Stage 2A 可以保留局部修正，但不再生成最终面向用户的完整 `suggestion`。

### Stage B：Diagnostic Adjudication & Aggregation

负责把多个 observation 解释成一个稳定的学习问题：

```json
{
  "utteranceId": "u_3",
  "status": "RISK",
  "rootCause": "LEXICAL_SELECTION",
  "confidence": 0.88,
  "evidenceType": ["semantic_usage", "collocation"],
  "signalIds": ["obs_12", "obs_13"],
  "focus": "propaganda",
  "learningIssue": "普通产品推广场景下不应使用 propaganda",
  "suggestion": "I want to promote my website.",
  "alternatives": ["I want to market my website."]
}
```

Stage B 负责：

- 判断 `ERROR / RISK / UNNATURAL / OPTIONAL`；
- 将多个底层 signals 聚合为一个 `rootCause`；
- 为判断增加 `confidence` 和 `evidenceType`；
- 在确认意图后生成完整推荐表达；
- 保留必要的 alternatives，但不追求唯一正确答案。

Stage B 不负责：

- 决定用户当前最应该学习什么；
- 直接生成 Top Habit；
- 改变语言事实以迎合用户目标。

### Stage 3：Goal Filter & Learning Priority

Stage 3 根据用户目标、重复度、严重度、置信度和学习价值，决定展示什么：

```text
诊断事实
    ↓
用户目标过滤
    ↓
学习优先级
    ↓
Top Habit / Growth Card / Score
```

## 顶层表达状态

底层可以继续保留大量 pointId，但面向用户的状态固定为四种：

| 状态 | 意义 | 默认展示 | 计入统计/评分 |
|---|---|---:|---:|
| `ERROR` | 明确违反规则或造成明显表达失败 | 是 | 是 |
| `RISK` | 可以理解，但可能造成歧义或语境风险 | 是 | 是，权重较低 |
| `UNNATURAL` | 正确且可理解，但明显偏离常规表达 | 按 Profile | 按 Profile |
| `OPTIONAL` | 原句完全成立，只是存在其他表达方式 | 否 | 否 |

`OPTIONAL` 不得进入：

- `totalIssues`；
- `performanceScore`；
- `topHabit`；
- `growthCard`；
- 历史问题统计。

`ErrorLevel` 继续表示教育/评分严重度，不与表达状态混用：

```text
status：这个表达是否值得作为问题处理
errorLevel：这个问题如果成立，严重程度如何
```

## Root Cause 设计

第一版只定义有限根因，不追求一次建立完整语言本体：

```text
GRAMMAR_FORM
LEXICAL_SELECTION
COLLOCATION
REGISTER
FLUENCY
CODE_SWITCH
SEMANTIC_MISMATCH
```

允许多个 signals 归并到一个根因：

```text
LEXICAL_SELECTION
  ├── LEXICAL_GAP
  ├── SEMANTIC_MISMATCH
  └── COLLOCATION
```

产品层只显示一个学习点；底层仍保留 signals，便于调试、评测和未来重新聚合。

### 建议数据关系

```text
Utterance
  └── DiagnosticObservation[]
          ↓
      DiagnosticIssue[]
          ├── status
          ├── rootCause
          ├── confidence
          ├── evidenceType[]
          ├── suggestion
          └── alternatives[]
```

## Stage B 的实现策略

Stage B 不应默认对每句话再增加一次完整 LLM 调用。建议采用混合实现：

### B1：确定性聚合层

不调用 LLM，负责：

- 同句、同 span、同 pointId 去重；
- 根据 pointId 映射初始 rootCause；
- 明确语法规则错误直接归为 `ERROR`；
- `OPTIONAL` 永远不进入统计和评分；
- 对重复底层 signal 合并；
- 计算基础 confidence。

### B2：模糊诊断层

只对以下候选调用 LLM：

- `SEMANTIC_MISMATCH`；
- `REGISTER / PRAGMATICS`；
- `UNNATURAL` 与 `OPTIONAL` 的边界；
- 需要结合上下文判断的表达；
- 有多个推荐表达且必须确认原意的句子。

因此实际调用链为：

```text
Stage 2A LLM：发现候选信号
    ↓
Stage B1 Code：去重、聚合、规则裁决
    ↓
Stage B2 LLM：只处理模糊候选
    ↓
Stage 3 Code：Goal Filter + Priority
    ↓
Stage 3 LLM：只生成行动卡/总结文案
```

## Top 3 实施计划

### P0：引入表达状态

效果：极高  
成本：中  
当前架构可落地：是

- [ ] 在 Stage 2/B 的结构化输出中增加 `status`。
- [ ] 增加 `ERROR / RISK / UNNATURAL / OPTIONAL` enum。
- [ ] 修改 DTO、Schema、解析器和前端类型。
- [ ] `OPTIONAL` 不计入 `totalIssues`、评分、Top Habit 和成长卡。
- [ ] 前端区分「错误」「注意」「更自然」；`OPTIONAL` 默认隐藏。
- [ ] 增加合法口语、明确错误、明显不自然、可选变体四类测试样例。

验收标准：

- 原句完全成立但存在更漂亮改写时，不会被计为问题；
- `ERROR` 和 `UNNATURAL` 不再共用同一展示语义；
- `OPTIONAL` 不影响分数和 Top Habit；
- 历史旧数据没有 `status` 时可以兼容读取。

### P1：增加 Root Cause 并按根因聚合

效果：极高  
成本：中  
当前架构可落地：是

- [ ] 增加 `rootCause`、`signals`、`learningIssue` 字段。
- [ ] 实现 pointId → signalType → rootCause 映射。
- [ ] 对同一句中的重叠 signals 去重。
- [ ] Action Card 改按 rootCause 聚合，而不是直接按底层 errors 计数。
- [ ] `totalIssues` 按 Diagnostic Issue 计数。
- [ ] 评分避免同一根因的多个 signals 重复扣分。
- [ ] Stage B 生成最终 `suggestion`，Stage 2A 只保留局部修正。

验收标准：

- 一句话命中多个底层信号时，默认只出现一个学习点；
- `propaganda` 示例可以聚合为 `LEXICAL_SELECTION`；
- Top Habit 的证据仍能回溯到原句和底层 signals；
- 诊断结果可以解释“为什么聚合成这个问题”。

### P2：增加固定学习目标 Profile

效果：高  
成本：中高  
当前架构可落地：是

第一版只增加三个 Profile：

```text
COMMUNICATION_FIRST
DAILY_NATURALNESS
GRAMMAR_ACCURACY
```

- [ ] 增加用户 Profile 字段或独立配置表。
- [ ] 增加设置页面和默认 Profile。
- [ ] 分析请求携带 Profile。
- [ ] Goal Filter 只改变展示、优先级、评分权重和反馈深度。
- [ ] Profile 不得改变语言事实判断。
- [ ] 为每个 Profile 定义 status 展示策略和评分权重。

建议策略：

| Profile | 重点展示 | 处理方式 |
|---|---|---|
| `COMMUNICATION_FIRST` | `ERROR`、高风险 `RISK` | 弱化轻微自然度问题 |
| `DAILY_NATURALNESS` | `ERROR`、`RISK`、明显 `UNNATURAL` | 强调日常搭配和语域 |
| `GRAMMAR_ACCURACY` | `ERROR`、Grammar rootCause | 提高语法问题优先级 |

验收标准：

- 同一句语言事实在不同 Profile 下不发生改变；
- 只改变展示深度、排序和评分权重；
- 默认用户不选择 Profile 时行为与当前系统兼容；
- Profile 不会使 `OPTIONAL` 进入错误统计。
