# 行动卡例句影子跟读设计

**日期：** 2026-10-06  
**状态：** 设计已确认，待写实施计划  
**范围：** 对话分析详情页「行动卡」Top 1–3 每张卡预览的例句（每卡 ≤2 句，共 ≤6 句）  
**相关：** 行动卡设计见 [`../../achieved/conversation-analysis-action-cards/2026-08-01-design.md`](../../achieved/conversation-analysis-action-cards/2026-08-01-design.md)

---

## 1. 目标

用户在行动卡里看到 AI 改好的句子后，能立刻「听原声 → 跟读 → 拿到分数」，把改对的表达说出口。

成功标准：

- 预览例句中有 `suggestion` 且与原句不同的，都出现跟读入口。
- 跟读后 2 秒内（排队除外）看到 0–100 分和逐词命中高亮。
- 跟读不可用时（服务未开、模型加载失败、TTS 失败），页面其它功能不受影响。

非目标（本期不做）：

- 保存录音或得分、历史记录、进步曲线；
- 音素级发音打分、韵律 / 音高曲线对比；
- 行动卡以外的句子（句子级检查列表、复习卡）。

## 2. 打分方案：离线识别 + 单词比对

### 2.1 为什么是这个方案

- 免费、数据不出服务器，2 核 4G 能承受（模型常驻约 200–300MB，单句约 0.5–1 秒，待实测）。
- 能回答「改好的句子有没有完整、按顺序说出来」，这正是行动卡练习的目标。
- 局限：识别模型会「自动纠正」发音（think 读成 sink 仍可能判对），所以分数代表**完整度与可懂度**，不代表发音准确度。界面文案不叫「发音分」，叫「跟读得分」。

### 2.2 识别

- 引擎：[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache-2.0）Java API，`OfflineRecognizer`（非流式）。
- 模型：`sherpa-onnx-zipformer-gigaspeech-2023-12-12`，仅用 int8 encoder + decoder + joiner + `tokens.txt`。
  - 选 transducer 而不是 Whisper / Moonshine：后两者语言模型强，会把读错的句子「脑补」成正确文本，分数虚高。
- 输入：16kHz 单声道 PCM16 WAV（前端转换好），时长上限 20 秒。

### 2.3 比对与计分

1. **归一化**（目标句与识别文本同一套规则）：转小写；连字符视为空格；去掉除词内撇号外的标点（保留 `don't`、`it's`）；按空白切词。
2. **不做词形还原**：产品练的是语法，把 went 说成 go 应算错。
3. **含数字的目标词不计分**：目标句写 `3`，识别结果是 `three`，无法可靠对齐；这类词显示为中性，不进分母。
4. 对两串词求最长公共子序列（LCS），命中的目标词标记 `hit=true`。
5. `score = round(命中词数 / 计分词数 × 100)`；计分词数为 0 时不打分，返回 400。
6. `passed = score ≥ 60`（可配置）。

返回逐词结果（按目标句顺序），供前端高亮：

```json
{
  "score": 82,
  "passed": true,
  "recognizedText": "i have been working here for three years",
  "words": [
    {"text": "I", "hit": true, "scored": true},
    {"text": "have", "hit": true, "scored": true},
    {"text": "3", "hit": false, "scored": false}
  ]
}
```

`words[].text` 保留目标句原始大小写和标点，便于直接渲染。

## 3. 原声：edge-tts 小服务

### 3.1 形态

- 代码放在本仓库 `services/edge-tts/`：FastAPI + [edge-tts](https://github.com/rany2/edge-tts)，一个接口 `POST /v1/tts`，入参 `{text, voice}`，返回 `audio/mpeg`。
- Docker 部署，与 ERRANT 同一模式；端口 **只映射到 `127.0.0.1:8001`**，不开安全组。
- 常驻内存约 50MB。

### 3.2 风险与兜底

- edge-tts 调用的是微软 Edge「大声朗读」的非官方接口，可能被限流或改协议失效。
- 缓解：
  1. 后端按 `sha256(voice + "\n" + text)` 把 mp3 缓存到磁盘，同一句只向微软请求一次；
  2. 后端拿不到音频时返回 503，前端自动改用浏览器 `speechSynthesis` 朗读；
  3. 协议变化时 `pip install -U edge-tts` 并重建镜像。

### 3.3 参数

- 默认音色 `en-US-AriaNeural`，可配置。
- 慢速播放由前端 `audio.playbackRate = 0.75` 实现，不额外合成。

## 4. 后端设计

### 4.1 包与组件

新建包 `com.khankiddo.learning.shadowing`：

| 组件 | 职责 |
|------|------|
| `ShadowingProperties` | `app.shadowing.*` 配置（见 4.4） |
| `ShadowingSentenceResolver` | 校验分析属于当前用户（`findByAnalysisIdAndUserId`），按 `sentenceId` 取 `suggestion`；不存在或为空时报 400 |
| `SpeechRecognizerHolder` | 启动时加载 sherpa-onnx 识别器（仅 `enabled=true`），`@PreDestroy` 释放；并发控制（见 4.3） |
| `WavPcmDecoder` | 解析 16kHz 单声道 PCM16 WAV 为 `float[]`，校验格式与时长 |
| `ShadowingWordMatcher` | 纯函数：归一化 + LCS + 计分，返回 2.3 的结构 |
| `EdgeTtsClient` | `RestClient` 调 `POST /v1/tts`，仿照 `ErrantAnnotatorClient` |
| `ShadowingAudioCache` | 磁盘缓存读写；写入用临时文件 + 原子 rename |
| `ShadowingController` | 3 个接口（见 4.2） |

### 4.2 接口

前缀 `/api/shadowing`，均需登录。

| 方法与路径 | 说明 |
|------|------|
| `GET /status` | `{scoringEnabled, ttsEnabled}`；前端据此决定是否展示跟读入口 |
| `GET /analyses/{analysisId}/sentences/{sentenceId}/audio` | 返回目标句 mp3（优先缓存）；TTS 未开或失败返回 503 |
| `POST /analyses/{analysisId}/sentences/{sentenceId}/score` | `multipart/form-data`，字段 `audio`（WAV）；返回 2.3 的结果 |

接口只接收 id、不接收任意文本，避免被当成免费 TTS / 识别服务滥用。

### 4.3 并发与过载

- 同时识别数 `max-concurrent`（默认 1），排队上限 `max-queue`（默认 2）。
- 正在识别 + 排队已满时，新请求立即返回 429「当前跟读人数较多，请稍后再试」；排队等待超过 10 秒同样返回 429。
- 识别器未就绪（未开启或模型加载失败）返回 503「跟读打分暂不可用」。
- 模型加载失败只记日志，不阻止应用启动。

### 4.4 配置

```yaml
app:
  shadowing:
    enabled: ${SHADOWING_ENABLED:false}
    admin-only: ${SHADOWING_ADMIN_ONLY:false}
    model-dir: ${SHADOWING_MODEL_DIR:}
    num-threads: 1
    max-concurrent: 1
    max-queue: 2
    max-audio-seconds: 20
    pass-score: 60
    tts:
      enabled: ${SHADOWING_TTS_ENABLED:false}
      base-url: ${SHADOWING_TTS_BASE_URL:http://127.0.0.1:8001}
      voice: en-US-AriaNeural
      cache-dir: ${SHADOWING_TTS_CACHE_DIR:./data/tts-cache}
      connect-timeout: 2s
      read-timeout: 15s
```

识别与 TTS 两个开关独立：只开 TTS 时可以听原声，但没有打分。

`admin-only=true` 时，非管理员调用 `/status` 得到两个 `false`，调用其余接口返回 403；用于上线初期灰度。

### 4.5 依赖引入

- sherpa-onnx 未发布到 Maven Central。把 `sherpa-onnx-jvm-<ver>.jar`、`sherpa-onnx-native-lib-linux-x64-<ver>.jar`、`sherpa-onnx-native-lib-osx-aarch64-<ver>.jar` 放进 `backend/lib/`，以 `system` scope 引入，并为 `spring-boot-maven-plugin` 开启 `includeSystemScope`。
- **两个平台的原生库都打进 jar**：线上 jar 是在 Mac 上用 `package.sh` 打的，按操作系统选 profile 会把 Mac 的库打进线上包。实施时需确认两个原生库 jar 内的资源路径不冲突。
- jar 体积约增加 20MB。

## 5. 前端设计

### 5.1 组件

| 文件 | 职责 |
|------|------|
| `src/api/shadowing.ts`、`src/types/shadowing.ts` | 3 个接口封装与类型；音频接口以 blob 获取（`<audio>` 无法带 JWT 头） |
| `src/composables/useWavRecorder.ts` | `getUserMedia` + `MediaRecorder` 录音，`decodeAudioData` + `OfflineAudioContext` 重采样到 16kHz 单声道，编码 PCM16 WAV；最长 15 秒自动停止 |
| `src/components/conversation/ShadowingPractice.vue` | 单句跟读条：原声（含 0.75×）、跟读 / 停止、结果展示 |

### 5.2 挂载位置

- `ActionCardsPanel` 加载时请求一次 `GET /status`，把 `analysisId` 与开关传给 `HabitEvidencePreview`。
- `HabitEvidencePreview` 仅在「有 suggestion 且与原句不同、有 sentenceId、功能已开」时渲染 `ShadowingPractice`。
- 不影响证据弹窗里的 `SentenceAnalysisCard`。

### 5.3 交互状态

`idle → recording → scoring → result`，另有 `error`。

- **原声**：首次点击拉取 mp3 并缓存成 object URL；503 时改用 `speechSynthesis`。
- **录音**：浏览器不支持或用户拒绝麦克风时提示原因；非 HTTPS 环境同样提示。
- **结果**：分数徽章 + 逐词高亮（命中常规色、未命中下划线弱化、不计分词中性）+「识别结果：…」+「再试一次」。
- 样式只用 `--kk-*` token，不新增色板。

## 6. 测试

- 后端单测：`ShadowingWordMatcher`（大小写、标点、撇号、连字符、数字不计分、乱序、漏词、多词、空输入）；`WavPcmDecoder`（合法 WAV、错误采样率、超时长、截断文件）；`ShadowingAudioCache`。
- 后端接口测试：`test` profile 下识别器关闭，用 mock 验证 200 / 400 / 429 / 503 与归属校验（他人的 analysisId 返回 400）。
- 前端：`npm run build` 类型检查通过；WAV 编码逻辑拆成纯函数，便于以后补测试。
- 人工验证：本机 Mac 跑通「原声 → 跟读 → 得分」；记录单句识别耗时与进程内存增量。

## 7. 部署

上线前另出操作清单，要点：

1. 本机下载模型并只保留 int8 文件，scp 到服务器 `/www/models/sherpa-onnx/zipformer-gigaspeech-2023-12-12/`。
2. 服务器构建并启动 `edge-tts` 容器：`--restart unless-stopped`，`-p 127.0.0.1:8001:8001`。
3. 宝塔环境变量新增：`SHADOWING_ENABLED`、`SHADOWING_ADMIN_ONLY=true`、`SHADOWING_MODEL_DIR`、`SHADOWING_TTS_ENABLED`、`SHADOWING_TTS_CACHE_DIR`（目录需 `www` 用户可写）。
4. 管理员验证内存与耗时没问题后，把 `SHADOWING_ADMIN_ONLY` 改为 `false` 并重启，对全部用户开放。
5. 前提：线上为 HTTPS（浏览器仅在安全上下文允许录音）。
