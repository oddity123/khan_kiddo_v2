## 总判断

**Top3 是按家族聚合的，不是按叶子。** 所有 rule 叶子的 `habitUnit` 都是 `family`：

```java
// HabitCardScorer#habitKey
case FAMILY -> point.familyId();   // 所有 rule 叶子走这条
```

所以 LLM 在 `ARTICLE_GENERIC_ZERO` 和 `ARTICLE_FIRST_MENTION` 之间选错，Top3 输出完全不变——两者聚合进同一个 `FAM_ARTICLE` 桶。**34 个 rule 叶子的判别负担，只换来 9 个桶。** 这是当前分类困难的根源：成本花在了不影响输出的维度上。

叶子唯一影响输出的地方是 `pickHighestScoringPointId` 选出的代表叶子，其 `titleZh` 进卡片副文。因此每个家族保留 1–3 个「教学动作不同」的叶子即可，再细就是纯负担。

同时，当前 `errorLevel` 校准把 `SVA_THIRD_PERSON` 标为 `FATAL`（每次命中 2.7 分，冠词只有 1.2 分），导致三单几乎必然霸占 Top3；但三单漏 s 基本不影响理解，属于典型「高频低危」。这是 Top3 质量的另一半问题。

**本期目标：叶子 39 → 22，家族 9 → 8（rule 通道），评分重新校准，历史数据零迁移。**

刻意**不**扩张覆盖面（连词 because/so、比较级、被动、动词补足语等缺口不在本期补）——扩张要等 `scripts/mine_knowledge_points.py` 在真实语料上验证过分布再说。唯一例外见「关键决策 5」。

## 关键决策



### 1. 用 `legacyAliases` 兼容历史数据，不改数据库、不留死叶子

`conversation_analysis_item.point_id` 已有旧 ID 存量。两个候选方案：


| 方案                               | 做法                                             | 取舍                                                                          |
| -------------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------- |
| A 保留 deprecated 叶子               | 旧 ID 留在 `points` 里标 deprecated，不进 schema enum  | 历史叶子精度 100% 保留，但字典膨胀到 53 条，且要改 `SchemaLoaderTest` 的 `enum ≡ allPointIds` 断言 |
| **B** `legacyAliases` **映射（采用）** | 字典 `points` 只有 22 条，另开 `legacyAliases` 段做旧→新映射 | 历史叶子精度降级为家族级精度，但字典干净、`SchemaLoaderTest` 断言不用改、实现量最小                         |


**采用 B。** 理由：历史统计按 `familyId` 聚合（见 pointid-problemtype-migration 的目标数据约定），alias 保住了家族归属，统计口径零影响；历史详情页只是叶子标题略泛。为这点精度保留 31 条死数据不划算。

**不做一次性 UPDATE 改存量数据**——不可逆，且字典还会再迭代。

### 2. `family.otherPointId` 改为可空

`PointDictionary#fromDocument` 现在强制每个 family 必须有 `otherPointId` 且存在于 points：

```java
for (FamilyDefinition family : familiesById.values()) {
    if (!StringUtils.hasText(family.otherPointId())) {
        throw new IllegalStateException("知识点字典 familyId=" + family.familyId() + " 缺少 otherPointId");
    }
    ...
}
```

要删掉 9 个家族级 `*_OTHER`（`ARTICLE_OTHER`、`NOUN_NUMBER_OTHER`、`AGREEMENT_OTHER`、`TENSE_OTHER`、`VERB_PATTERN_OTHER`、`PREPOSITION_OTHER`、`WORD_FORM_OTHER`、`PRONOUN_OTHER`、`FLUENCY_OTHER`）就必须放宽这条。改成：`otherPointId` 为空时跳过校验，非空时仍校验存在性。

改后只有两个家族保留 `otherPointId`：`FAM_SENTENCE` → `STRUCTURE_OTHER`、`FAM_WORD_FORM` → `WORD_FORM_POS`；其余 9 个家族置空。

`HabitCardScorer#isCatchAllLeaf` 已经用 `StringUtils.hasText(family.otherPointId())` 做了空值保护，`pickHighestScoringPointId` 在「全是兜底叶子」时有 `orElseGet(...false)` 回退，都不需要改。

全局兜底 `PointDictionary.FALLBACK_POINT_ID = "STRUCTURE_OTHER"` **保持不变**，`STRUCTURE_OTHER` 继续作为唯一全局兜底叶子存在。

顺带把 `FAM_LEXICAL.otherPointId` / `FAM_CHINESE.otherPointId` 也置空——它们现在指向自己家族唯一的叶子，导致 `LEXICAL_GAP` / `CHINESE_CODE_SWITCH` 被 `isCatchAllLeaf` 误判为兜底叶。对单叶子分组无实际影响，但语义是错的。

### 3. `errorLevel` 重新校准：`FATAL` 只给真正妨碍沟通的

`FATAL` 只留三个：`TENSE_WRONG_CHOICE`、`MISSING_SUBJECT_OR_BE`、`WORD_ORDER`。

`SUBJECT_VERB_AGREEMENT` 从 `FATAL` 降到 `BASIC`（最重要的一处改动）。`THERE_BE`、`VERB_FORM_AFTER_AUX`、`PROGRESSIVE_BE` 同样从 `FATAL` 降到 `BASIC`——它们是形态问题，不是理解障碍。

### 4. `fixability` 收敛为三档

`0.9`（规则明确，讲一次就能改）/ `0.6`（要练）/ `0.3`（只能一个个攒）。取消 0.65、0.75、0.8、0.85、0.95 这些没有依据的中间值。`STRUCTURE_OTHER` 特例给 `0.5`，让兜底叶子的分数低于所有实叶子。

### 5. 唯一的覆盖扩张：`WORD_ORDER`

`QUESTION_STRUCTURE` + `NOUN_CLAUSE_ORDER` 合并成 `WORD_ORDER`，并在 `titleZh` 里把**状语位置**一起纳入（`I yesterday went` / `I very like it`）。状语语序是汉语母语者最高频的错误之一，当前字典完全没有落点，只能被迫打 `STRUCTURE_OTHER`。这是本期唯一放宽的覆盖面，因为它是「合并顺带」而非新开家族。

### 6. 下调 `FLUENCY` / `CHINESE` 的 `impactWeight`（连带效应，必须一起改）

三单从 `FATAL` 降到 `BASIC` 后，rule 通道单次命中最高只有 1.80 分，而 `CHINESE_CODE_SWITCH` 是 2.50、`FLUENCY_INCOMPLETE` 是 2.30——两者会取代三单成为新的霸榜项。

`FAM_CHINESE.impactWeight` 1.25 → **1.0**，`FAM_FLUENCY.impactWeight` 1.15 → **1.0**。校准后两者各 2.00 分，仍高于 rule 顶格的 1.80（「别说中文」「把句子说完」确实该优先），但不再碾压。

注意 `CHINESE_CODE_SWITCH` 在中文通道注入时代码里用固定 `BASIC`（2.0），不读字典的 `STYLE`，这个行为不改。

### discriminators（5 → 3 条）

合并家族后，`TENSE_VS_VERB_PATTERN`（两个家族并成 `FAM_VERB`）和 `WORD_FORM_PRIORITY`（两个 gerund 叶子并成一个）自动失效，删除。

```json

  { "id": "ARTICLE_VS_PLURAL",
```

## 成功标准


| 指标                         | 期望                                    |
| -------------------------- | ------------------------------------- |
| LLM 可选叶子数                  | 39 → 22                               |
| discriminator 条数           | 4（prompt 内）→ 3                        |
| `STRUCTURE_OTHER` 占比       | 下降（家族级 `*_OTHER` 逃生口被移除，但细叶子边界更清晰）    |
| golden familyAcc           | 上升，至少不下降（**主指标**，Top3 靠 family 聚合）    |
| golden leafAcc             | 不与旧值直接对比（叶子集合已变），只作为新基线记录             |
| Top3 中 `FAM_AGREEMENT` 出现率 | 明显下降（三单不再霸榜）                          |
| Top3 出卡率                   | 上升（家族 9 → 8，`MIN_HIT_COUNT = 2` 更易达成） |
| JSON 解析失败率                 | 不变差                                   |


`STRUCTURE_OTHER` 占比这项要注意反向风险：移除家族级 `*_OTHER` 后，原本会落到 `ARTICLE_OTHER` 的样本可能改落 `STRUCTURE_OTHER`。若 golden 显示该占比不降反升，说明某个家族的细叶子仍不够，届时**只给该家族补一个叶子**，不要把 9 个 `*_OTHER` 整体加回来。
