**日期：** 2026-08-02

**相关：** [`../learning-loop-gaps/2026-08-02-lingotrace-gap-priority.md`](../learning-loop-gaps/2026-08-02-lingotrace-gap-priority.md)、[`../../achieved/conversation-analysis-action-cards/`](../../achieved/conversation-analysis-action-cards/)

## 1. 问题与目标

此前补给项被拆成「今日复习队列 / 掌握度 / 错句小练习」等并列概念，加上竞品多 Tab（单词 / 纠错 / 句型），心智偏散。

Kiddo 产品理念偏向小孩成长；对外需要 **至繁归于至简** 的一个主词。

**目标：** 全站以卡片为基调；可复习的长期资产统一为 **成长卡**。队列、掌握度、练习不再单独做成产品线命名。

---

## 2. 核心模型

### 2.1 全站卡片基调

界面与信息架构按「卡」理解，而不是「报表行 + 另一套复习系统」。

### 2.2 原卡 vs 成长卡

| 名称 | 是什么 | 职责 |
|---|---|---|
| **原卡** | 分析报告里的现有一块：原句 + 建议说法 + 若干错误点 | 证据 / 原料；偏「看见问题」 |
| **成长卡** | 从原卡（或其它来源）提炼出的可复习单元 | 习得 / 复习；偏「学会一件事」 |

原卡不拆成「错句一行」和「建议一行」两张；现有报告块即一张原卡。

### 2.3 最小可习得点

成长卡按 **最小习得特性** 设计：

> 一张成长卡只对应一个可以习得的知识点。

不得把整场对话、或整包原卡（多错误点未拆清）原样当成一张成长卡来复习。每张成长卡只钉住一个最小可习得点。  
MVP 自动铸卡不做「一习惯拆多张」；收藏路径若日后拆卡，仍遵守本原则。

### 2.4 对外主词

- 对外统一：**成长卡**（与 Kiddo / 小孩成长理念一致）
- **习惯** 是成长过程的一部分，不是并列产品线；Top 习惯是铸卡来源之一，不再单独叫「Top 习惯卡」给用户
- 「今日复习队列」= 今日到期的成长卡  
- 「掌握度」= 成长卡上的状态  
- 「小练习」= 成长卡的二级模式（MVP 不做）

MVP 首批 `type`：`habit` / `vocab`；后期可扩，仍服从「一张卡一个最小可习得点」。

## 3. 铸卡规则

| 来源 | 时机 | 规则 |
|---|---|---|
| **Top1 习惯** | Stage3 **总结完成后异步**经铸卡助手 | **整场只铸 1 张**（`type=habit`，LLM 生成正反面 + Tool 落库）。多句原卡作证据上下文，不拆多张 |
| **Top2 / Top3** | 分析页展示 | **不**自动铸；用户收藏后再铸 |
| **词汇** | 现有路径 | 不会的中文表达 → `type=vocab` 成长卡（不强调、不新增「点词生成」主路径） |
| **其它原卡** | 用户主动收藏 | 点收藏才铸；不替用户堆卡 |

**原则：**

1. 原卡留在报告里；成长卡才进入「今日翻卡」。
2. Stage3 只负责总结；铸卡走 **LLM 生成草稿 + Gateway 显式落库**，异步不堵总结（见 §6）。
3. Top1 单卡跑通后，再决定是否扩到 Top2/3 或允许一习惯多卡。

```
原卡（原句 + 建议 + 错误点）
  └─ GrowthCardMintGateway（异步）
       ├─ MintAssistant.generate → GrowthCardDraft（只生成 front/back）
       └─ GrowthCardStore.persistNewOrGet（业务方显式落库）
            └─ 成长卡（翻面 · 状态 · 可选出题）
```

---

## 4. 状态、翻卡与每日路径

### 4.1 状态

挂在成长卡上，三档：

`生疏` → `模糊` → `已掌握`

（对外文案可再打磨；工程上可用 enum。）

### 4.2 自评与到期（极简调度）

翻面后用户自评，同时改状态与下次出现日：

| 自评 | 状态 | 下次进入「今日成长卡」 |
|---|---|---|
| 不会 | 生疏 | 1 天后 |
| 模糊 | 模糊 | 3 天后 |
| 会了 | 已掌握 | 不进今日（仍可在卡包打开） |

新铸卡默认 `生疏`，`nextDueAt = 今天`（或铸卡完成后即可翻）。

不做完整 SM-2；间隔仅上表三档。

### 4.3 复习方式

| 阶段 | 方式 |
|---|---|
| **MVP** | Anki 式：翻面 + 上表自评 |
| **后做** | 卡上二级动作：生成 1～3 道小题再考察 |

### 4.4 每日主路径与入口分工

**复习 / 复盘不走首页。** 首页「自动生成知识卡片」区块只做能力展示（DEMO 闪卡自动演示），不是练习入口。

正式路径（后续单独页面）：

> 进入「成长卡复习」页，把 `nextDueAt ≤ 今天` 且未「已掌握」的卡一张张翻完并自评；复盘也在同域页面承接，不塞进首页。

不单独命名「复习队列」产品；入口表达为今日待翻的成长卡即可。

分析页职责：展示原卡与 Top 习惯；Stage3 总结先出，Top1 成长卡异步落下（详情侧栏可看已生成卡片）；其余经收藏或现有词汇路径进入卡包。

## 5. 成长卡 type 与正反面模板（MVP）

| type | 来源 | 正面 | 背面 |
|---|---|---|---|
| `habit` | Top1 经 **LLM 铸卡助手** 生成 | 最小可习得点（人话提问/提示） | 目标说法 / 要点 + 可对照证据 |
| `vocab` | 中文表达原料 → Gateway 直写 Store（可不经 LLM） | 中文（词/短语） | 英文表达 |

共用字段（示意）：`id`, `userId`, `type`, `status`, `nextDueAt`, `front`, `back`, `sourceAnalysisId?`, `sourceRef?`, `createdAt`, `updatedAt`。

正反面文案由 LLM 按「一张卡一个最小可习得点」生成，**不是**把 `ActionCardDto` 字段原样拷贝。

---

## 6. 铸卡架构：生成助手 + 业务方显式落库

成长卡能力收在同一包，避免逻辑散落在分析 Service / 多个 Factory。**落库不是 Tool**：LLM 只产出草稿，由 Gateway / ReviewService 显式写 Store。

### 6.1 包边界

建议包：`com.khankiddo.learning.growth`。

| 单元 | 职责 |
|---|---|
| **GrowthCardMintAssistant** | `@AiService`：通用知识卡生成 → 返回 `GrowthCardDraft(front, back)`；**不**挂 Tool、不落库 |
| **GrowthCardMintGateway** | 对外唯一入口：`mintAfterAnalysis`；组装上下文 → `assistant.generate` → `store.persistNewOrGet` |
| **GrowthCardStore** | 幂等持久化、按分析/到期查询 |
| **GrowthCardReviewService** | 非 LLM：今日列表、自评调度、收藏（直接调 Store） |

`ConversationAnalysisServiceImpl` 只做：persist 后发事件 / 详情读 mint 状态；**不写铸卡文案、不拼正反面**。

### 6.2 时序

```
Stage3 总结完成并 persist
  → AFTER_COMMIT 事件
  → GrowthCardMintGateway.mintAfterAnalysis（虚拟线程）
  → MintAssistant.generate → Draft
  → Store.persistNewOrGet（Gateway 显式）
  → 详情「生成中…」→ ready
```

1. Stage3 **仍只做总结**；铸卡异步，不堵总结。  
2. 耗时主要来自 LLM；失败可重试，不回滚分析。  
3. Assistant 可被其它业务复用（只生成）；是否落库、type / sourceRef 由调用方决定。

### 6.3 生成契约

`GrowthCardDraft`：`front`、`back`。

铸卡助手 System：通用知识卡能力（正反面、不编造证据）。Top1 habit 等具体任务写在 ContextBuilder 的 userMessage；Gateway 负责 type / sourceRef / 落库。

## 7. MVP 边界

### 7.1 做

1. 原卡 / 成长卡概念落地（模型 + 文案口径）
2. 成长卡统一对象：`habit` / `vocab` 正反面 + 状态 + `nextDueAt`
3. **内聚铸卡包**：MintAssistant（只生成）+ Gateway（显式落库）；Stage3 后异步铸 Top1
4. 词汇：中文表达原料经同一 Gateway 直写 Store
5. 其它靠收藏（走同一 persist 能力）
6. 独立复习页：到期成长卡翻面自评（§4.2；首页不做练习）

### 7.2 不做

- Top2/3 自动铸卡；Top1 拆多张
- 卡上再生成多道语法微练（二级模式后做；与「铸练习卡」本身不同）
- 完整 Anki SM-2
- 句型库、日历热力、正式 PWA 作为本设计主线
- Mirror 对方 JSON 导入 / ChatGPT 项目指令
- 「习惯 / 队列 / 掌握度」并列产品命名
- 把铸卡逻辑写进 `ConversationAnalysisServiceImpl` / 无 LLM 的字段拷贝 Factory
- 把落库包装成 Agent Tool 交给模型调用

### 7.3 成功标准

用户分析完成后先看到总结，随后看到 LLM 生成的一张 Top1 成长卡；词汇/收藏也进同一卡模型；次日能翻今日卡并自评——不再问「练完还能干嘛」。

## 8. 与旧文档的关系

| 旧说法（补给表） | 归一后 |
|---|---|
| 今日复习队列 | 今日到期的成长卡（`nextDueAt ≤ 今天`） |
| 掌握度 / 复习状态 | 成长卡状态 + 极简到期 |
| 错句小练习（P1） | 成长卡二级模式；MVP 不做 |
| Top 习惯行动卡 | 诊断展示 + Stage3 后异步经铸卡助手为 Top1 铸 1 张成长卡 |

`learning-loop-gaps` 优先级表仍可作对照清单；实现与对外叙事以本文为准。

回检（focus-recheck）仍为 backlog，不阻塞本设计。

## 9. 已决开放问题

| # | 结论 |
|---|---|
| 1 拆分与上限 | Top1 **只铸 1 张**；整场自动铸卡上限 = 1。多句原卡挂证据 |
| 2 调度 | 自评映射：不会→生疏/1 天；模糊→模糊/3 天；会了→已掌握/不进今日 |
| 3 type 与模板 | MVP 仅 `habit` + `vocab`，正反面见 §5（由 LLM 生成） |
| 4 延迟降级 | **先异步铸**（Stage3 仍只做总结）；失败可重试、不拖垮分析 |
| 5 铸卡形态 | MintAssistant 只生成 Draft；Gateway 显式落库；流水线只调 Gateway |
