# Connection：跨对话学习闭环

状态：产品方向已确认；分阶段实施规划，尚未实现。各阶段开工前完成对应接口与技术验证，不将未验证的 ChatGPT 页面能力视为承诺。

## 1. 已确认的产品边界

- 首版服务 Chrome/Edge 桌面 ChatGPT 网页；移动端后续单独规划。
- 每次分析独立对话的全部内容，不做新增消息分析或跨会话拼接。
- 下次练习默认新开 ChatGPT 对话，不要求分析后立即复练。
- 个性化推荐与跨对话记忆仅面向登录用户；现有访客与分享链接导入保持兼容。
- 默认采用场景对话，系统自动挑选少量重点；用户可换一组，无需逐项勾选。
- 注入只填入输入框，由用户发送；已有草稿不得覆盖。
- 本轮业务闭环：分析 → 更新重点 → 下次发起练习 → 再次分析 → 展示有证据的变化。

## 2. 核心概念

| 概念 | 职责 | 与现有能力的关系 |
| --- | --- | --- |
| 学习画像 | 用户目标、场景偏好、长期能力概况 | 首版只做可选目标/场景，完整画像后置 |
| 学习证据 | 对话中的错误、正确使用及来源 | 复用 analysisId、sentenceId、pointId，补充正向证据 |
| 当前重点 | 跨对话聚合后当前值得练的少量内容 | 不等同于单次报告 Top，不直接修改成长卡自评 |
| 练习计划 | 冻结本次目标、场景、来源与提示词 | 复用 PracticePromptService，新增自动选取职责 |
| 进步反馈 | 复发、正确使用或证据不足 | 独立于本次分析结果生成 |

结构化状态与证据由 MySQL 管理；RAG 负责查找相关历史例句，不作为掌握状态真源。不引入图数据库。

必须区分：用户自评会了、提示下正确、独立正确、没有观察机会。一次未报错不能推导掌握；一次正确也不自动推导长期掌握。

## 3. 仓库事实与设计影响

- 扩展目前只在分享页注入，background 向 KK 页面 sessionStorage 传递内容，不持有 KK 凭证。普通对话读取与新对话注入均需单独验证。
- 网站通过 localStorage 的令牌发送 Bearer 请求。扩展账号连接是新增能力，不能简单把网站长期令牌传入 ChatGPT 页面。
- 分析已有 pipeline、analyzeAndPersist 与 SSE API；扩展需要可恢复查询的任务资源，不能将弹窗生命周期等同于任务生命周期。
- 持久化使用 SecurityUtils 获取用户；后台任务必须显式、安全地传递用户身份，不依赖请求线程上下文偶然存在。
- conversation_analysis_item 主要保存错误明细，缺失错误不能证明正确使用。正向回检需要包含用户原句的独立证据判断。
- 已有成长卡、证据表、pointId 与漏斗事件表，应优先复用；旧回检备忘由本方案承接，不单独再建入口。

## 4. 落地顺序与验收

### P0：连接可行性验证

交付：当前对话读取适配器与新对话注入的验证结论、样例夹具、支持范围。

- 验证普通文本、语音转写、长对话、编辑/重新生成分支、SPA 路由切换与尚未完成的回复。
- “全部内容”指当前选定分支的完整对话；不能把仅已渲染片段静默当作全部。无法确认完整性时提示并提供分享导入。
- 不读取其他历史会话，不把 ChatGPT 登录凭证上传 KK。读取策略必须隔离在适配器中。
- 验证从新页面填入提示词，到用户首次发送后获得稳定对话标识的可行性。
- 验收：可确认角色与顺序、完整性、会话标识；失败可恢复。若核心能力不可行，先修订交互方案再启动 P1。

### P1：登录用户一键分析

交付：账号连接、整段提交、持久化任务状态、简短反馈与报告入口；可独立灰度上线。

- 建议采用 KK 登录页授权后的一次性交换机制，扩展持有可撤销的专用凭证；限定来源、兑换有效期与权限，凭证不进入 ChatGPT 内容脚本或 URL。
- 新增任务创建/查询能力，复用现有分析流水线。持久化 queued/running/succeeded/failed 状态；弹窗关闭后任务继续，重开可恢复查询。
- 后台任务显式绑定发起用户并逐次校验归属；有界执行、超时和重启后失败恢复，不自动无限重试消耗额度。
- 相同用户、来源对话及内容指纹的重复提交返回已有任务/结果；并发点击不能重复执行。内容改变仍整段分析，不做增量；同来源修订不重复累计历史频次。
- 保留分享入口与现有网站 SSE；新增能力通过开关灰度。
- 验收：重复点击、断网重试、弹窗关闭、服务重启、过期登录和跨用户访问均有明确结果。

### P2：自动安排下次练习

交付：插件“开始今天的练习”、推荐预览、换一组、新对话注入与计划记录。

- 新增推荐编排服务，先用规则聚合历史 pointId 和到期成长卡。按近期复发、学习目标相关性、到期情况排序；提供选择原因。
- 建议默认一个主要薄弱点，最多两个表达；数量、历史窗口等参数在后端 Properties/yml 集中管理。
- 复用提示词组装器，场景从模板配置选择；没有历史时提供通用场景，不伪造个人弱项。
- 计划冻结来源证据与提示词，后续记忆变化不能改写旧计划。换一组不计为完成练习。
- 新开对话并填入；首次发送建立会话标识后绑定计划。绑定前保留扩展本地待关联状态，切换账号清理。
- 关联失败不猜测匹配：分析仍可作为自由聊天；向用户提供一次手动关联入口。
- 验收：隔日启动无需寻找历史页面；多标签页不串计划；已有草稿不覆盖；注入不等同于已练习。

### P3：证据驱动的回检

交付：跨会话重点、练习结果反馈、独立证据记录。本阶段完成才算本轮最小闭环交付。

- 分析成功持久化后独立触发回检；失败可重试，不阻断报告。处理按分析/来源修订幂等。
- 普通聊天检查少量当前重点；计划会话额外检查计划目标。分析本身不被历史错误标签诱导。
- 对每个目标记录复发、正确使用或证据不足，引用用户句子；排除注入的训练指令、助手示范与纯粘贴答案作为独立能力证据。
- 从已保存对话提取用户原句并验证引用；仅错误表不足以支持正向结论。判断结果标明提示辅助情况与不确定性。
- 更新聚合状态，但不自动覆盖成长卡自评。进步反馈最多展示少量有出处的变化。
- 新增证据删除/重算处理：删除来源分析时清理派生证据与失效引用；不能在记忆中保留被删除原文。
- 验收：未用到目标不算掌握、重复分析不增加频次、证据属于当前用户、回检失败不影响主分析、删除后不再展示旧证据。

### P4：长期画像（后续增强）

- 可查看和修正的目标、常用场景与偏好；用户明确输入优先于模型推断。
- 结合多次独立使用与跨场景证据形成趋势，不以单次表现生成确定的能力等级。
- 增加记忆管理、暂停某重点及清除能力；RAG 为推荐补充合适例句。

## 5. 接口与数据边界

实施时按阶段冻结实际路径与 DTO；以下是必须具备的接口职责，不是已存在的接口。

| 接口组 | 最小能力 |
| --- | --- |
| 扩展连接 | 发起连接、登录授权、一次性交换、查询连接、撤销 |
| 分析任务 | 提交完整内容和来源标识，返回任务标识；查询状态、错误与 analysisId |
| 练习计划 | 获取推荐、创建冻结计划、绑定来源会话、查询计划 |
| 学习状态 | 获取当前重点、查询本次回检反馈；后续支持用户修正 |

新增独立的扩展连接、分析任务、练习计划、学习证据与聚合状态职责。不要将这些职责堆入 ConversationAnalysisServiceImpl、GrowthCardMintGateway 或大型详情 SFC；旧入口最多委托。

所有用户资源按服务端身份隔离，不信任客户端 userId。协议配置由后端统一暴露非敏感项。状态迁移、新增表及索引需提供已有生产库升级脚本，不能只修改建库 DDL。

历史错误可用于推荐；正向证据只从新回检开始记录，不推断历史已掌握状态。历史初始化可重跑，缺 pointId 的历史材料不强行归类。

## 6. 测试、发布与效果判断

- 后端：H2 验证任务状态、归属、幂等、重启恢复、证据更新与删除；用固定模型返回测试回检判断，真实模型评测单独运行。
- 扩展：提取夹具覆盖角色、语音字幕、分支和不完整页面；手工验证 ChatGPT 真实页面、首次发送关联和多标签。
- 前端/扩展分别构建；涉及新提示词时遵守 resources/AGENTS.md，先跑固定样例再小范围真实验证。
- 各阶段独立发布与开关，先个人账号及少量真实用户；回滚关闭新入口，保留原分享导入与网站分析。
- 复用漏斗事件能力记录：读取成功、分析提交/完成、推荐展示、计划创建、注入成功、关联成功、后续分析完成。事件中不存原文或凭证。
- 主要观察首次分析后再次分析、计划后产生实际用户练习证据的比例；同时看提取失败率、任务失败率、回检成本。注入点击不能算学习完成。

## 7. 后续需技术验证的事项

当前没有待确认的高层产品选择。以下在对应阶段开发前明确，不能假设已验证：

1. 当前 ChatGPT 页面完整对话与语音字幕提取方式、支持边界。
2. 正式扩展 ID、连接授权桥接机制与撤销/到期策略。
3. 生产部署副本数、任务执行与重启恢复策略。
4. pointId 及成长卡表达身份的归并规则、回检引用的可靠提取方式。

不在本轮实施：增量对话分析、手机入口、自动发送 ChatGPT 消息、图数据库、完整长期画像、全量历史 LLM 重分析。
