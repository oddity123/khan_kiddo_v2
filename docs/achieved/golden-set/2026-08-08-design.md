# Stage2 黄金标准（Golden Set）设计

日期：2026-08-08（归档 2026-08-09）  
状态：**已归档**（比对内核 + harness + 主集 3 case 已落地；复跑见 `eval/golden`）  
归档说明：[`README.md`](./README.md)  
数据准备（User 取数手册）：`2026-08-08-data-prep-todo.md`  
相关：`eval/drift`（稳定性）、`docs/todo/stage2-prompt-slim`（prompt 精简后需评测）

## 1. 目标

- 留存少量冻结样本作为**准确性**参照，后续 Stage2 结果与之比对，能量化「改 prompt / schema / 模型」是变好还是变差。
- 与已有 **Drift Harness** 分工：drift 测稳定性（免标注）；golden 测准确性（需标准答案）。
- 数据形式便于自动比对（precision / recall / pointId 命中），不依赖 suggestion 措辞。

## 2. 范围与非目标

**范围（只做 Stage2 抽取层）**

- 输入：冻结的英文 learner utterance 列表（不经 Stage1）。
- 输出比对：句级有错/无错 + 错误级 `pointId`（支持可接受集合与家族级软匹配）。
- 下游 Stage3 / 分数：不进 golden；分数由公式从 items 导出，给定抽取结果可复现。

**非目标（本期不做）**

- Stage1 切分 / 路由评测
- Stage3 总结文案评测
- suggestion 字符串/语义相似度硬指标
- 多模型投票标注流水线、标注 UI
- 线上 Schema 把 `pointId` 改成 list

## 3. 已定决策摘要

| 决策点 | 选择 |
|--------|------|
| 评测层 | 仅 Stage2 |
| 比对粒度 | 错误级 `(utterance, pointId)` |
| 输入边界 | 冻结英文 utterance 列表 |
| 标注方式 | 单路强模型 + 人工抽查后冻结 |
| 首版规模 | 迷你集：约 20–30 句 / 3 个 case（clear / confusable / legit；不含 asr） |
| 叶子歧义 | 线上仍单 `pointId`；gold 用 `acceptablePointIds[]` |
| 落地形态 | JSON case + `GoldenStatistics` + opt-in Java harness（对齐 drift） |

## 5. 数据契约

### 5.1 `meta.json`

```json
{
  "id": "clear-error-01",
  "category": "clear_error",
  "title": "冠词/时态明确错误",
  "notes": "",
  "goldSource": {
    "model": "claude-opus-4",
    "dated": "2026-08-08",
    "reviewedBy": "oddity",
    "reviewStatus": "spot_checked"
  }
}
```

`category` 枚举（主集）：

- `clear_error` — 明确语法错误
- `legit_spoken` — 合法口语（真阴性）
- `confusable_point` — 相邻 pointId 易混

（`asr_noise` 曾规划，已移出主黄金集，见 data-prep-todo。）

### 5.2 `input.json`

```json
{
  "utterances": [
    { "id": "u1", "text": "It have a example." },
    { "id": "u2", "text": "That makes sense." }
  ]
}
```

- `id`：稳定主键，比对以它为准。
- harness 将 `text` 按序组成 `List<String>` 喂给现有 Stage2 入口（与 pipeline 中 `analyzeGrammar(englishSentences, …)` 同边界）。

### 5.3 `gold.json`

```json
{
  "version": 1,
  "utterances": [
    {
      "id": "u1",
      "expectError": true,
      "errors": [
        {
          "errorId": "e1",
          "primaryPointId": "SVA_THIRD_PERSON",
          "acceptablePointIds": ["SVA_THIRD_PERSON", "AGREEMENT_OTHER"],
          "span": "have",
          "note": ""
        }
      ],
      "suggestionHint": "It has an example."
    },
    {
      "id": "u2",
      "expectError": false,
      "errors": []
    }
  ]
}
```

**硬指标字段**：`expectError`、`acceptablePointIds`（须含 `primaryPointId`）。  
**参考字段（不算分）**：`span`、`note`、`suggestionHint`。  
**约束**：`expectError: false` ⇒ `errors` 为空；`acceptablePointIds` 均须为字典合法 pointId。

## 6. 比对算法

### 6.1 原文对齐

1. 规范化：`trim` + 连续空白压成单空格。
2. 用规范化后的 `item.originalSentence` 映射到 `input.utterances[].id`。
3. 映不上 → `unaligned_actual`（单独计数，不进主 P/R）。
4. gold `expectError: true` 且无对应 actual item → 漏报（FN）。

若同 case 内规范化后文本重复，以 `input` 中首次出现的 `id` 为准，并在 README 中约定：**同一 case 内避免重复原文**。

### 6.2 句子层（检出）

| gold \ actual | 无 item | 有 item |
|---------------|---------|---------|
| `expectError=false` | TN | FP |
| `expectError=true` | FN | TP（进入错误层） |

- Precision = TP / (TP + FP)
- Recall = TP / (TP + FN)
- F1 = 调和平均

### 6.3 错误层（仅 TP 句）

- Gold：每个 error 的 `acceptablePointIds` 集合。
- Actual：该句 `errors[].pointId` 列表（一对一占用）。
- **叶子命中**：贪心匹配——每个 gold error 若存在尚未占用的 actual `pointId ∈ acceptablePointIds` 则命中。
- **家族命中**：经 `PointDictionary.require(pointId).familyId()` 映射后，同样贪心；acceptable 家族 = 各 `acceptablePointIds` 的 family 并集。
- 叶子准确率 = 叶子命中数 / gold error 总数（全语料或按 case 聚合）。
- 家族准确率同理。

多余的 actual errors（未匹配上任何 gold error）计入 **多余检出**，写入报告明细，本期不并入主 F1（避免与句级 FP 双重惩罚；句级已用「有错/无错」约束误报）。

### 6.4 报告主指标

- 句检出 P / R / F1
- 叶子 pointId 准确率、家族准确率
- 误报句列表、漏报句列表、未对齐 actual
- 按 `category` 分组的小结表

## 7. 标注与冻结流程（§4）

1. **选句**：从真实对话 / drift 种子抽出英文句，覆盖主集 3 类；拼成约 3 个 case，合计约 20–30 句。
2. **写 `input.json` + `meta.json`**：先冻结输入，再标答案。
3. **强模型出初稿**：用与线上不同家族的强模型，按**同一套 pointId 字典与 Stage2 规则摘要**生成候选 `gold.json`（可脚本或手工粘贴）。
4. **人工抽查**：重点看客观类、真阴性、易混对；调整 `acceptablePointIds`（边界叶子可并列），改 `reviewStatus`。
5. **冻结**：合并进仓库后视为基线；改 gold 须改 `meta.goldSource.dated` 并在 PR 说明原因。
6. **回归**：改 prompt/schema 后跑 harness，对比上次报告指标；翻转句肉眼看变好/变差。

标注提示：强模型应输出与 `gold.json` 同构的结构，或先出线上 Schema 形 JSON 再由脚本转成 `acceptablePointIds`（初稿可 `acceptable = [primary]`）。

## 8. Harness 行为

- Opt-in：`-Dgolden=true`（默认不随 `mvn test` 跑，避免烧额度）。
- 可选：`-Dgolden.modelId=<id>`，语义对齐 `drift.modelId`。
- 调用路径：直接走 Stage2（`GrammarAnalysisUserPromptBuilder` + 现有 grammar 分析客户端 / 与 pipeline 同边界的可测入口），**跳过 Stage1**。
- 若现有公开 API 只能跑全 pipeline：实现计划中优先抽出「仅 Stage2」的 package-visible / 测试友好入口，避免用字幕绕一圈污染评测。
- 与 drift 相同：真实跑不断言失败；`GoldenStatisticsTest` 用 fixtures 随 CI 绿。

示例命令（实现后写入 README）：

```bash
cd backend
export $(grep -E '^[A-Za-z_][A-Za-z0-9_]*=' ../.env | grep -v '&' | xargs)
./mvn.sh -q test \
  -Dspring.profiles.active=test \
  -Dgolden=true \
  -Dtest=ConversationGoldenHarness
```

## 9. 成功标准（首版）

- 目录契约与至少 **1 个完整 case**（含真阴句）入库；目标凑齐主集 3 类各 ≥1 case（不含 asr_noise）。
- `GoldenStatisticsTest` 覆盖：TN/TP/FP/FN、叶子/家族命中、可接受集合、未对齐。
- 本地能跑通 harness 并产出 Markdown 报告。
- 与 drift 文档交叉引用：准确性看 golden，稳定性看 drift。

## 10. 刻意不做 / 后续可升级

- 双模型投票（曾议方案 B）：样本变大或分歧多时再加。
- suggestion 语义评测、Stage1/3 golden。
- CI 上对指标设硬阈值（先报告、后人肉门槛）。

## 11. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 强模型与线上同源偏差 | 换厂商；抽查真阴与易混；acceptable 集合吸收边界 |
| 原文对齐失败 | 稳定 `utterance.id`；禁止 case 内重复原文；报告 unaligned |
| 叶子边界主观 | 双指标（叶子 + 家族）+ acceptablePointIds |
| 误把稳定性当准确性 | 文档与目录与 drift 严格分离 |
